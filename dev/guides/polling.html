Polling and progress ​

Request a property without blocking the caller, distinguish a pending result from a completed value, and inspect progress. Both scalar and indexed properties support polling. A normal blocking read computes inline on its caller's task unless an executor changes that policy.

Scalar polling ​

fetchproperty starts or observes a scalar computation and passes the result and status to a callback. This example holds the computation behind a channel, so the pending state is reproducible without timing assumptions.

julia
using DynamicObjects

@dynamicstruct struct Work
    gate::Channel{Nothing}
    "A gated scalar computation."
    value = (take!(gate); 42)
    scaled(gain) = gain * value
end

work = Work(Channel{Nothing}(1))
pending = fetchproperty(work, :value) do result, status
    result
end
pending isa Pending
true

The callback runs with a Pending handle while work is in flight. It can render a waiting state without fetching the value. Calling fetch on that handle blocks until the computation completes or throws.

julia
put!(work.gate, nothing)
fetch(pending)
42

Indexed polling ​

fetchindex is the corresponding operation for an argument-taking property. Its callback also receives (result, status). A completed entry returns its value immediately; an unfinished entry returns a handle.

julia
result = fetchindex(work.scaled, 2) do value, status
    value
end
value = result isa Pending ? fetch(result) : result
value
84

Polling does not require @cached. Disk persistence is a separate choice. Repeated requests for the same entry share its in-flight computation. force=true on fetchindex invalidates the requested entry before requesting it again; use the cache guide to choose the invalidation scope.

Progress ​

An object supplies a Treebars progress root by default. A property's docstring labels its progress node. Reads visible inside a property body attach under the reader; the status passed to a poll callback is the node for the observed computation, or nothing when progress is disabled.

julia
status = getstatus(work.scaled, 2)
(root_exists = work.__status__ !== nothing,
 entry_status_exists = status !== nothing)
(root_exists = true, entry_status_exists = true)

Pass __status__ = nothing when constructing an object to turn its progress off. To label a root, provide a Treebars node as that keyword. The fetchindex! and fetchproperty! overloads accept a progress node when a caller needs explicit attachment. @fetch! threads those reads through a block; ordinary property bodies already attach their visible reads.

Queued work ​

@queued on an indexed property routes its computations through the package's process-wide job_queue. configure_queue! sets its concurrency cap: max_running=0 admits work immediately; a positive cap makes later work wait in FIFO order. Cached values never queue, and callers with the same arguments share one memoized computation. A queued computation gives back its slot when it waits for another queued computation, allowing its child to run.

An application can also create a separate queue and submit a QueuedCall. This call returns its computed value through fetch without creating a property cache entry.

julia
queue = DynamicObjects.JobQueue(max_running=2)
call = DynamicObjects.QueuedCall(() -> sum(abs2, [1, 2, 3]))
DynamicObjects.enqueue!(queue, call)
result = fetch(call)
result
14

Use queue_settings and queued_items to inspect admission. observe_queue! registers an enqueue observer; unobserve_queue! removes it. abandon_queued! withdraws waiting work without interrupting computations already admitted.

Worker processes ​

Set workers=1 through configure_queue! to run admitted @queued property computations in a separate Julia process. The root object's type must belong to a package the worker can load. workers=0 keeps execution in the requesting process. Queueing changes where work runs; it does not add context to cache keys.

The configuration reference contains the complete worker_start and worker_preload contract, including eager and lazy startup, restart behavior, and the distinction between omitting the preload list and clearing it. Use worker_status to inspect the process and restart_worker! to replace it. carry_to_worker! registers named package scoped values for transport; unregistered scoped values do not travel. Worker computations can send messages through send_to_requester to a handler registered with on_requester_message!.

Executors and errors ​

Framework code can supply a Deferred executor, with property_executor selecting it for a declaration. await_deferred lets its blocking waits cooperate with the scheduler. Keep synchronous computations as ordinary properties unless the application needs a scheduling policy.

A failed body is reported through PropertyComputationError. unwrap_error retrieves the underlying exception for error reporting. Invalidation retracts a cached computation; it does not forcibly stop arbitrary Julia code already running. See ComputeAbandoned for work abandoned before execution.

Cached signal analysis uses with_compute_trace to distinguish work from cache reuse without relying on elapsed times.
